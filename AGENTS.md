# Правила работы над AKFIX

## Проект

- Что это: единое веб-приложение AKFIX для сборщиков, водителей, логистов, приёмки и администраторов.
- Владелец продукта и DRI: Евгений, AKFIX RUS.
- Стек: Node.js 20+, CommonJS на сервере, ванильные HTML/CSS/JavaScript на клиенте, PWA без сборщика.
- Точки входа: `server.js`, `public/`, `receiving-test/`.
- Данные: Bitrix24, Google Sheets «Отгрузка 2», Excel приёмки, локальное серверное хранилище и Telegram.
- Нельзя рисковать: токенами, webhook, PIN-кодами, фотографиями, клиентскими данными и рабочими назначениями.
- Работа: отдельная ветка `codex/*` или `feature/*`, публикация только через PR в `main`.

## Порядок работы

1. Перед изменениями определить затрагиваемые сценарии и источники данных.
2. Для неоднозначной задачи сначала показать план. Поля Bitrix24 и столбцы таблицы не угадывать.
3. Менять только файлы задачи, не форматировать весь проект.
4. Перед коммитом выполнить `pnpm run check` и пропорциональную ручную проверку.
5. Обновлять README и документы, если изменилось поведение, настройка или интеграция.
6. Публиковать рабочую ветку через PR; прямой push и force-push в `main` запрещены.

## Безопасность и границы

- Не добавлять секреты и реальные клиентские выгрузки в Git.
- Не скрывать ошибки молчаливыми выдуманными значениями.
- Не подключать зависимости и внешние CDN без необходимости и проверки.
- Не удалять и не переписывать пользовательские изменения вне задачи.
- Не отключать тесты, линтер или CI ради зелёного результата.
- Новые или существенно изменённые JavaScript-файлы начинают со строки `// @ts-check`, если это совместимо с их окружением.

## Определение готовности

- существующие и новые тесты проходят;
- линт, форматирование изменённых JS-файлов и проверка типов проходят;
- основной пользовательский сценарий проверен вручную;
- в диффе нет посторонних файлов и секретов;
- документация соответствует поведению;
- изменения опубликованы через PR.

## Финальный отчёт

После изменения кода сообщить: пользовательский результат, затронутые файлы, соседние риски, выполненные проверки и оставшиеся ограничения.
