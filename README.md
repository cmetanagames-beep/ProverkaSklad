# AKFIX — единое приложение склада и логистики

Один веб‑сервис AKFIX для сотрудников склада, водителей, логистов и администратора. После входа приложение определяет роль пользователя и открывает нужный рабочий раздел. Отдельные URL — это экраны одной системы, а не самостоятельные приложения.

Рабочий адрес: [proverka.akfixdev.ru](https://proverka.akfixdev.ru/)

## Роли и разделы

| Роль          | Раздел        | Назначение                                                                                                           |
| ------------- | ------------- | -------------------------------------------------------------------------------------------------------------------- |
| Сборщик       | `/`           | Заказы из Bitrix24, проверка товара и палет, обязательные фотографии, история и офлайн‑очередь                       |
| Приёмщик      | `/receiving/` | Загрузка Excel, фактическое количество, срок годности в формате «месяц и год», ячейка хранения и выгрузка результата |
| Водитель      | `/driver/`    | Рейсы на сегодня и завтра, история, данные доставки, фото экспедиторской и офлайн‑отправка                           |
| Логист        | `/logist/`    | Контроль отгрузок, проверка и исправление данных Bitrix24, назначение водителя, просмотр экспедиторской              |
| Администратор | `/admin.html` | Пользователи и роли, привязка имени водителя к таблице, заказы, комментарии, фотографии и Telegram‑группы            |

## Источники данных

- **Bitrix24** — сделки, поля доставки, стадии, комментарии и фотографии.
- **Google Sheets «Отгрузки»** — дата отгрузки, номер заказа, водитель, склад, документы, ЧЗ, перебивка и способ доставки.
- **Excel приёмки** — перечень товаров и плановое количество для отдельного процесса приёмки.
- **Telegram** — две независимые группы: проверка склада и экспедиторские расписки. Уже выбранные группы запрашиваются напрямую у Telegram и остаются видимыми в админке после перезапуска без повторной команды `/start`.

Связь заказа из таблицы с Bitrix24 выполняется по полю Bitrix **«Номер счета»**. Сначала приложение ищет точное значение из таблицы (например, `1231313`), затем совместимый вариант с префиксом (`3424` → `АФУТ-003424`). Внутренний ID элемента Bitrix не считается номером заказа.

## Основные сценарии

### Сборщик

1. Открывает назначенный заказ.
2. Проверяет наличие товара и типы палет.
3. Делает обязательные фотографии каждой палеты.
4. Результат сохраняется в Bitrix24 и отправляется в Telegram после завершения проверок складов.

### Водитель

1. Открывает вкладку **«Сегодня»** или **«Завтра»**.
2. Смотрит назначенные ему рейсы и данные заказа.
3. Для транспортной компании прикладывает фото экспедиторской.
4. Отправка сначала сохраняется на телефоне. Большие фотографии с iPhone автоматически уменьшаются перед загрузкой без потери читаемости документа; для Safari предусмотрен дополнительный способ декодирования, а сервер принимает оригиналы до 30 МБ. Сервер сохраняет собственную копию фото и сразу отпускает водителя, а запись в Bitrix24 и отправку в Telegram выполняет своей очередью с повторными попытками. Телефон дополнительно повторяет загрузку при восстановлении связи, открытии приложения и каждые 30 секунд, пока фото не принято сервером.
5. Сервер фиксирует завершение рейса после успешной записи в Bitrix24, до отправки в Telegram. Поэтому временная ошибка Telegram не возвращает требование повторно фотографировать расписку на другом устройстве; Telegram повторяется из очереди телефона без повторной записи в Bitrix24.
6. При обновлении PWA экран водителя автоматически перезагружается на новую версию; скрипт имеет версию в URL, чтобы iPhone не продолжал выполнять устаревший кеш.
7. В завершённых рейсах и календарной истории водитель видит сохранённое фото экспедиторской расписки и может открыть или скачать его. Маршрут фотографии доступен только водителю, которому принадлежит рейс.
8. Запись в Bitrix24 и отправка в Telegram защищены от повторного выполнения. При временной ошибке Telegram сервер сохраняет задачу и повторяет её с увеличивающимся интервалом, даже если приложение водителя закрыто. Подтверждённая Telegram-отправка повторно не выполняется.
9. Очередь фотографий водителя обрабатывает новые отправки первыми. Ошибка одной старой записи не блокирует остальные фотографии; неотправленные записи остаются на телефоне и повторяются автоматически.
   При повторной ошибке приложение показывает точный код ответа сервера и сохраняет его вместе с количеством попыток, не удаляя фотографию.
   Safari перед каждой попыткой создаёт свежий файл из сохранённых байтов; онлайн-очередь приложения и фоновая очередь Service Worker не запускаются одновременно.
10. Рейс идентифицируется по дате и номеру заказа, а не по позиции строки Google Sheets. Перемещение строк и одинаковая позиция заказа в разные дни не переносят статусы и локальную очередь между сегодняшними и завтрашними рейсами.
   Старая запись очереди с несколькими номерами заказов также распознаётся после объединения строк в общий рейс.
   Если тестовый рейс вернули или строку перенесли на соседнюю дату, сервер дополнительно сверяет номер заказа по дате старой записи, сегодня, вчера и завтра.
11. Если «Наименование» в Google Sheets пустое, приложение водителя показывает название из заголовка сделки Bitrix24 без служебного префикса и номера сделки.
12. Строки одного клиента с одинаковыми датой, складом, водителем, способом доставки, адресом и контактом получателя из Bitrix24 объединяются в один общий рейс. Заказ с отличающимся или незаполненным адресом либо контактом остаётся отдельным. Одна экспедиторская расписка сохраняется во всех сделках группы, все сделки переводятся в «Принято на проверку», а в Telegram отправляется одно сообщение со списком заказов.
13. После успешного завершения сделка автоматически переводится в стадию Bitrix24 **«Принято на проверку»**.

Статусы в списках используют единый язык: серый — работа не начата, синий — информация, зелёный — выполнено, жёлтый — ожидание фоновой операции, красный — требуется действие сотрудника.

Фото экспедиторской напрямую сохраняется в поле сделки `ufCrm19ExpeditorReceipt` (**«Фото экспедиторской расписки»**) и отправляется в отдельную Telegram‑группу. Комментарий в таймлайне сделки не создаётся. ID стадии **«Принято на проверку»** приложение получает из списка стадий Bitrix24 по точному названию и повторно использует уже существующую интеграцию складской проверки.

Администратор может повторно открыть ошибочно завершённый тестовый рейс через защищённый API `POST /api/admin/driver/reset` с `orderNumber`: локальное завершение и сохранённое фото удаляются, поле экспедиторской очищается, а сделка возвращается на стадию **«Передан на сборку»**.

Последние 20 необработанных серверных ошибок доступны администратору через `GET /api/admin/server-errors`. Журнал хранится только в памяти процесса и содержит время, маршрут и технический код без тела запроса, фотографий и клиентских данных.

Для доставки **«ТК СДЭК»** блок полей доставки из Bitrix24 водителю не показывается. Номер заказа и данные из таблицы остаются видимыми.

### Логист

1. Видит все сегодняшние отгрузки и заказы, требующие внимания.
2. Открывает заказ и проверяет сведения Bitrix24.
3. Исправляет доступные поля или меняет назначенного водителя.
4. Проверяет завершение рейса и загруженную экспедиторскую.

### Приёмка

1. Сотрудник загружает новый `.xlsx` или `.csv`.
2. Указывает фактически принятое количество, месяц и год срока годности и ячейку.
3. При необходимости делит товар на несколько размещений.
4. Завершает приёмку и скачивает итоговый Excel.

Приёмка является разделом единого приложения и использует общее нижнее меню **«Заказы / Приёмка / История»**. При загрузке другого документа приложение сначала запрашивает подтверждение, сохраняет текущую приёмку до успешного чтения нового файла и позволяет повторно выбрать даже тот же самый файл.

При первом открытии приложения показывается двухсекундная заставка с фирменным логотипом AKFIX. Форма входа остаётся скрытой до завершения проверки сессии, поэтому авторизованный сотрудник не увидит её кратковременное мигание. При переходах между разделами в рамках той же сессии заставка повторно не запускается.

## Офлайн‑режим

- список заказов и ранее открытые карточки сохраняются на устройстве;
- сегодняшние и завтрашние рейсы водителя хранятся отдельно;
- фотографии и завершения, сделанные без интернета, попадают в локальную очередь;
- после восстановления соединения приложение автоматически повторяет отправку;
- состояние очереди нельзя считать доставленным в Bitrix24 или Telegram, пока синхронизация не завершилась.

Подробнее: [офлайн‑работа и обновления](docs/OFFLINE.md).

## Единый визуальный стиль

Основной интерфейс использует логотип AKFIX, красный акцент `#cf0a2c`, тёмный текст, белые рабочие поверхности, серый фон и бирюзовый цвет только для успешных состояний. Базовые правила:

- реальные логотипы и понятные текстовые кнопки;
- одинаковая высота основных кнопок — около 54–56 px;
- радиус полей и кнопок — 8–10 px;
- красный цвет обозначает основное действие или внимание;
- бирюзовый обозначает успешное завершение;
- мобильная ширина и крупные области нажатия обязательны для рабочих экранов.

## Проверка проекта

Требуется Node.js 20 или новее.

```bash
pnpm install
pnpm run check
```

`pnpm run check` проверяет синтаксис серверных и клиентских файлов, запускает автоматические тесты, линтер, форматирование изменённых JavaScript-файлов и проверку типов. Перед публикацией также проверяются рабочие маршруты `/`, `/driver/`, `/logist/`, `/receiving/`, `/admin.html`, `/health` и PWA‑манифест.

В проект интегрирован адаптированный `middle-kit`: ESLint и Prettier проверяют новые и постепенно переводимые на единый стиль JavaScript-файлы, TypeScript выполняет проверку файлов с `// @ts-check`, pre-commit hook запускает локальный контроль, а GitHub Actions повторяет тесты и поиск секретов независимо от компьютера разработчика. Старые компактные клиентские файлы защищены проверкой синтаксиса и функциональными тестами без массового переформатирования.

Разовая установка локального Git hook:

```bash
pnpm run hooks
```

Правила разработки находятся в [AGENTS.md](AGENTS.md), краткая инструкция — в [ПАМЯТКА-РАЗРАБОТЧИКУ.md](ПАМЯТКА-РАЗРАБОТЧИКУ.md).

Последняя полная проверка интерфейса: **19.08.2026**. На мобильной ширине проверены вход, сборка, приёмка, водительские рейсы и карточка заказа, логистика и администрирование. Рабочие экраны скрыты до завершения восстановления сессии: форма входа не должна мигать при открытии приложения. Пока заказы загружаются, показывается единое состояние загрузки без преждевременного сообщения «Заказы не найдены».

Инструкция поддерживает закрытие клавишей Escape, удерживает клавиатурный фокус внутри окна и возвращает его на кнопку, с которой инструкция была открыта. Вкладки водителя на узком экране перестраиваются в компактный блок 2×2. Администратор и логист используют общую адаптивную рабочую оболочку. В пустой приёмке отображается одна основная кнопка загрузки; после загрузки файла доступна отдельная безопасная команда «Загрузить другой Excel» с подтверждением замены.

## Локальный запуск

1. Скопируйте и заполните переменные из `.env.example`.
2. Выполните `npm install`.
3. Выполните `npm start`.
4. Откройте `http://localhost:8787`.

## Безопасность

- секреты, токены ботов, webhook Bitrix24 и PIN‑коды нельзя добавлять в GitHub или клиентские файлы из `public/`;
- в production обязателен длинный случайный `SESSION_SECRET`;
- роли проверяются сервером, а не только скрытием кнопок в интерфейсе;
- загруженные файлы и пользовательские данные должны проходить серверную проверку.
