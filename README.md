# AKFIX — единое приложение склада и логистики

Один веб‑сервис AKFIX для сотрудников склада, водителей, логистов и администратора. После входа приложение определяет роль пользователя и открывает нужный рабочий раздел. Отдельные URL — это экраны одной системы, а не самостоятельные приложения.

Рабочий адрес: [proverka.akfixdev.ru](https://proverka.akfixdev.ru/)

## Роли и разделы

| Роль | Раздел | Назначение |
|---|---|---|
| Сборщик | `/` | Заказы из Bitrix24, проверка товара и палет, обязательные фотографии, история и офлайн‑очередь |
| Приёмщик | `/receiving/` | Загрузка Excel, фактическое количество, срок годности в формате «месяц и год», ячейка хранения и выгрузка результата |
| Водитель | `/driver/` | Рейсы на сегодня и завтра, история, данные доставки, фото экспедиторской и офлайн‑отправка |
| Логист | `/logist/` | Контроль отгрузок, проверка и исправление данных Bitrix24, назначение водителя, просмотр экспедиторской |
| Администратор | `/admin.html` | Пользователи и роли, привязка имени водителя к таблице, заказы, комментарии, фотографии и Telegram‑группы |

## Источники данных

- **Bitrix24** — сделки, поля доставки, стадии, комментарии и фотографии.
- **Google Sheets «Отгрузки»** — дата отгрузки, номер заказа, водитель, склад, документы, ЧЗ, перебивка и способ доставки.
- **Excel приёмки** — перечень товаров и плановое количество для отдельного процесса приёмки.
- **Telegram** — две независимые группы: проверка склада и экспедиторские расписки.

Связь заказа из таблицы с Bitrix24 выполняется по номеру заказа: `3424` → поле Bitrix **«Номер счета»** со значением `АФУТ-003424`. Внутренний ID элемента Bitrix не считается номером заказа.

## Основные сценарии

### Сборщик

1. Открывает назначенный заказ.
2. Проверяет наличие товара и типы палет.
3. Делает обязательные фотографии каждой палеты.
4. Результат сохраняется в Bitrix24 и отправляется в Telegram после завершения проверок складов.

### Водитель

1. Открывает вкладку **«Сегодня»** или **«Завтра»**.
2. Смотрит назначенные ему рейсы и данные заказа.
3. Для транспортной компании прикладывает фото экспедиторской.
4. Фото и сообщение связываются с найденной сделкой Bitrix24 и отправляются в отдельную Telegram‑группу.

Для доставки **«ТК СДЭК»** блок полей доставки из Bitrix24 водителю не показывается. Номер заказа и данные из таблицы остаются видимыми.

### Логист

1. Видит все сегодняшние отгрузки и заказы, требующие внимания.
2. Открывает заказ и проверяет сведения Bitrix24.
3. Исправляет доступные поля или меняет назначенного водителя.
4. Проверяет завершение рейса и загруженную экспедиторскую.

### Приёмка

1. Сотрудник загружает новый `.xlsx` или `.csv`.
2. Указывает фактически принятое количество, месяц и год срока годности и ячейку.
3. При необходимости делит товар на несколько размещений.
4. Завершает приёмку и скачивает итоговый Excel.

## Офлайн‑режим

- список заказов и ранее открытые карточки сохраняются на устройстве;
- сегодняшние и завтрашние рейсы водителя хранятся отдельно;
- фотографии и завершения, сделанные без интернета, попадают в локальную очередь;
- после восстановления соединения приложение автоматически повторяет отправку;
- состояние очереди нельзя считать доставленным в Bitrix24 или Telegram, пока синхронизация не завершилась.

Подробнее: [офлайн‑работа и обновления](docs/OFFLINE.md).

## Единый визуальный стиль

Основной интерфейс использует логотип AKFIX, красный акцент `#cf0a2c`, тёмный текст, белые рабочие поверхности, серый фон и бирюзовый цвет только для успешных состояний. Базовые правила:

- реальные логотипы и понятные текстовые кнопки;
- одинаковая высота основных кнопок — около 54–56 px;
- радиус полей и кнопок — 8–10 px;
- красный цвет обозначает основное действие или внимание;
- бирюзовый обозначает успешное завершение;
- мобильная ширина и крупные области нажатия обязательны для рабочих экранов.

## Проверка проекта

Требуется Node.js 20 или новее.

```bash
pnpm install
pnpm run check
```

`pnpm run check` проверяет синтаксис серверных и клиентских файлов, запускает автоматические тесты, линтер, форматирование изменённых JavaScript-файлов и проверку типов. Перед публикацией также проверяются рабочие маршруты `/`, `/driver/`, `/logist/`, `/receiving/`, `/admin.html`, `/health` и PWA‑манифест.

В проект интегрирован адаптированный `middle-kit`: ESLint и Prettier проверяют только изменённые JavaScript-файлы, TypeScript выполняет проверку файлов с `// @ts-check`, pre-commit hook запускает локальный контроль, а GitHub Actions повторяет тесты и поиск секретов независимо от компьютера разработчика.

Разовая установка локального Git hook:

```bash
pnpm run hooks
```

Правила разработки находятся в [AGENTS.md](AGENTS.md), краткая инструкция — в [ПАМЯТКА-РАЗРАБОТЧИКУ.md](ПАМЯТКА-РАЗРАБОТЧИКУ.md).

Последняя полная проверка интерфейса: **18.08.2026**. На мобильной ширине проверены вход, сборка, приёмка, водительские рейсы и карточка заказа, логистика и администрирование. Отдельные регрессионные тесты контролируют скрытие рабочего интерфейса до входа, отсутствие фоновых запросов без авторизации, вкладки водителя и единую кнопку выхода.

## Локальный запуск

1. Скопируйте и заполните переменные из `.env.example`.
2. Выполните `npm install`.
3. Выполните `npm start`.
4. Откройте `http://localhost:8787`.

## Безопасность

- секреты, токены ботов, webhook Bitrix24 и PIN‑коды нельзя добавлять в GitHub или клиентские файлы из `public/`;
- в production обязателен длинный случайный `SESSION_SECRET`;
- роли проверяются сервером, а не только скрытием кнопок в интерфейсе;
- загруженные файлы и пользовательские данные должны проходить серверную проверку.
